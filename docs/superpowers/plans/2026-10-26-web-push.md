# Web Push implementation plan

> Execute inline; user supplied full specification and explicitly requested simplest implementation without clarification.

**Goal:** Device-scoped daily Web Push in existing Từ Từ Settings, Vercel Node Functions and Upstash Redis.
**Architecture:** Existing static JS/hash router/SW remain. Add server/push shared modules + five /api/push routes (includes authenticated device test). Client owns a random local management capability, independent of Supabase accounts. Build injects only VAPID public key and daily/flexible mode. Existing font Be Vietnam Pro takes precedence over the generic old-font reference in the request.
**Spec:** User message sections 0–9; fixed Hobby cron `0 13 * * *`, flexible opt-in for 15-minute scheduler.

## Global constraints
- No account/login changes or other page redesign. Existing handwritten SW cache stays intact; import push event module.
- Daily mode enforces 20:00 Asia/Ho_Chi_Minh on server and client. Hobby may deliver20:00–20:59. Flexible mode compares per-device local time and date, maximum one daily notification.
- Validate 8KiB bodies, trusted push-provider HTTPS URLs, p256dh/auth keys, capability token, time/timezone. Same-origin mutations, rate limits, CRON_SECRET checks; no endpoint/secret logs.
- Only web-push and @upstash/redis runtime dependencies. No real keys committed, no live deployment from this task.
- Generic notification only (optional due counts/completion suppression omitted to avoid stale cross-device/account data).

## Review focus
- Concurrent/duplicate cron, failure retry, expired404/410 cleanup.
- Unauthorized settings/unsubscribe/test and SSRF attempts must fail safely.
- Browser permission denial, iOS install requirement, offline disable and failed storage must not report false success.
- Notification click focuses/navigates existing app tab or opens scope-safe review URL.
- Build/SW never expose private keys, Redis creds or cache API results.
